### Deploying (Docker / Kubernetes / CI)

1. **Credentials and data stay out of git and out of the image.** `.gitignore` and `.dockerignore` exclude `api_keys.json`, `pipeline_run_summary.json`, `notebook_data_sample.csv` and `validation_report*.csv` (real rows, and often > 50 MiB). The Dockerfile does `COPY . ./` and the default-deny `.dockerignore` decides what enters the image: the model / recipe `*.json` files do, credentials, run summaries and data samples never do.
2. **Local container** (the image runs as uid 10001, so the mounted key file must be readable by it):
```bash
docker build -t automl-model .
chmod 644 api_keys.json
docker run -p 8000:8000 -v "$PWD/api_keys.json:/secrets/api_keys.json:ro" -e API_KEYS_PATH=/secrets/api_keys.json automl-model
```
3. **Kubernetes:** publish the keys as a Secret, render the image reference, apply (the manifest creates a ConfigMap, the Deployment with a read-only root filesystem and non-root user, the Service, a PodDisruptionBudget and a HorizontalPodAutoscaler):
```bash
kubectl create secret generic dataset-tabular-ml-api-keys --from-file=api_keys.json=./api_keys.json
kubectl apply -f k8s.yaml
```
   `k8s.yaml` always contains a valid image name (the registry image when `--image_owner` / `IMAGE_OWNER` was set, otherwise the local `<app>:latest` with `imagePullPolicy: IfNotPresent` -- build it with `docker build -t <app>:latest .`). To deploy the image CI pushed, run `kubectl set image deployment/<app> <app>=<registry>/<owner>/<name>:<tag>`, or render both manifests in one step: `python render_manifests.py --image <registry>/<owner>/<name>:<tag> --host <your-domain>` (writes k8s.rendered.yaml and k8s-ingress.rendered.yaml; no hand-editing).
   Optional: `kubectl apply -f k8s-networkpolicy.yaml` restricts the pods' network (ingress only from the `ingress-nginx` namespace and the pods' own namespace -- change the label value if your ingress controller lives elsewhere; it only takes effect on clusters whose network plugin enforces NetworkPolicy). `kubectl apply -f k8s-ingress.yaml` adds TLS (create the `<name>-tls` secret and set the host first), a body-size cap and a cluster-wide rate limit at the edge. Pin the base image by digest with `docker build --build-arg PYTHON_IMAGE=python:3.11-slim@sha256:<digest> .`.
4. **CI (`.github/workflows/ci.yml`):** credential-file check -> Kubernetes manifest validation -> `tests/` -> no-pickle guardrail -> lint + Hadolint -> image build + Trivy vulnerability scan (pull requests build and scan only) -> push + rendered manifest (main branch). `.github/dependabot.yml` keeps the action / base-image / pip pins current.

Latency and PSI-drift monitoring run in a FastAPI BackgroundTask after the response (never inside it). The Docker image is built with ONE `COPY . ./` filtered by the default-deny `.dockerignore` (safe formats only, no pickle / joblib, no credentials). ## API reference

### `POST /predict/tabular`
Send raw, unprocessed feature values -- the server replays the exact preprocessing steps recorded in `feature_recipe.json` before scoring.

- Engineered columns listed under `derived_features` in `feature_recipe.json` (date parts, `geo_dist_km`, `<col>__freq`) are **computed by the server** from the raw columns (e.g. `trans_date_trans_time`, `lat`/`long`/`merch_lat`/`merch_long`); you may still send the engineered values yourself and they win.
- A feature that is **missing** from the request gets HTTP 422 naming it; send `null` for "unknown" (median-imputed). `ALLOW_MISSING_FEATURES=true` restores silent imputation.
- Binary models answer with the class at the **trained decision threshold**; override it per deployment with the `DECISION_THRESHOLD` environment variable (a number between 0 and 1) -- no retraining needed.
- API keys: `python create_api_key.py --owner my-service` (ships in this bundle).

```bash
curl -X POST http://localhost:8000/predict/tabular \
  -H "X-API-Key: <your-key>" -H "Content-Type: application/json" \
  -d '{"features": {"duration": 18.0, "credit_amount": 2250.0, "installment_commitment": 3.0, "residence_since": 3.0, "existing_credits": 1.0, "checking_status": "0<=X<200", "savings_status": "100<=X<500", "employment": "1<=X<4", "personal_status": "female div/dep/mar", "other_parties": "co applicant", "property_magnitude": "car", "other_payment_plans": "bank", "housing": "for free", "job": "high qualif/self emp/mgmt", "foreign_worker": "no"}}'
```
A response header `X-Model-Drift-Warning: true` appears if the live input distribution has drifted from the training baseline (`drift_baseline.json`, PSI-based).
